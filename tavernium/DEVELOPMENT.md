## 已实现

### 回复完成通知

- 主菜单新增「回复完成通知」，默认关闭，由用户主动开启并授予 Android 13+ 通知权限。
- 通过 SillyTavern 的 `getContext()` 与 `MESSAGE_RECEIVED` 接入；兼容 `eventTypes` / `event_types`，延迟初始化采用有上限的重试。
- 过滤首次问候、用户/系统/空消息、静默生成、代写、重复事件及可识别的流式失败、手动停止。
- 依据原生 Activity、屏幕和锁屏状态判断：后台、锁屏、防烧屏挂机时提醒；前台阅读时不提醒。
- 通知只包含通用的完成提示，不传输角色名或回复正文；回到前台清除提醒，点击提醒会解除挂机遮罩。
- 独立通知渠道，可从应用中的设置入口跳转到系统通知设置。

主要代码：`ReplyNotifier.java`、`assets/reply-notifications.js`，由 `MainActivity` 接入生命周期和菜单。

### 网页原生接口

- 新增 `BridgeSession`：每次顶层导航生成新的 256 位随机凭证，导航、渲染进程销毁、Activity 销毁时旧凭证失效。
- 凭证只保存在注入脚本闭包中；`saveBlob`、`noteNetActivity`、`replyReady` 都必须提供当前凭证。
- 页面信任边界改为同源（协议、主机、有效端口），并在脚本执行时再次校验顶层窗口和来源。
- 通知跨线程投递后再次验证凭证，避免页面切换后执行旧回调。

### 更新链路

- 清单来源允许 HTTPS 或回环/局域网 HTTP；下载地址必须绑定实际拉取的清单且与其同源。
- 清单与 APK 都禁用自动重定向，最多手动跟随五次同源跳转，每次跳转在联网前检查。
- 解析后的相对下载地址按实际清单 URL 解析，跨源条目被移除。
- 缓存复用和下载完成后都强制验证包名、签名、版本；清单提供 SHA-256 时必须匹配。
- 拒绝空证书集合、无效哈希和超大 APK（上限 128 MiB），失败时清理半截文件。
- 安装入口再次核对包名与证书；移除了签名校验失败后仍能继续安装的按钮。
- 修正 URL 工具将 `fc` / `fd` 开头域名误判为 IPv6 私有地址的问题，补齐标准 IPv6 解析。

签名配置、applicationId、`下载/SillyTavern/` 目录名称未更改。

### 服务器连接与账号凭据（最后一批）

- 新输入及已保存的服务器地址统一校验：公网使用 HTTPS；HTTP 仅接受私有/回环 IP、link-local 或 `localhost`。不依赖域名的 DNS 解析结果判断内网。
- WebView 普通初始 HTTP 请求遇到公网地址时返回明确的阻止响应；HTTPS 页面关闭混合 HTTP 内容。应用内顶层导航按同源判断。
- 原生缓存与下载请求只对配置的服务器同源地址附加 Basic 凭据；带凭据时禁用自动重定向，避免将认证头带到下一站。
- 主文档预取也限定为同源，并禁用自动重定向；WebView 的认证回调增加服务器主机和当前主页面检查。
- 「慢域名黑名单」提示改为读取实际超时时长，目前为 30 分钟，移除旧的六小时文案。

兼容性变化：原有公网 HTTP 配置需要改为 HTTPS；使用自定义内网域名（含 `.local`）的 HTTP 配置需要改为私有 IP 或 HTTPS。带 Basic 凭据的直连下载若返回重定向，目前会报告下载失败，需原作者按实际服务器决定后续处理。页面预取失败仍会回退 WebView。

### 挂机与系统栏整理

- 将遮罩、手势、提示计时和旧设置迁移移入 `IdleController`；Activity 继续负责 WebView 回调与帧率设置。
- 暂停时取消提示任务，重建网页时移除旧遮罩，销毁时清除任务、视图、Activity 和监听器引用。
- 修正系统取消滑动手势时可能误解除挂机的问题，损坏或无效的挂机设置恢复为关闭状态。
- 导航栏控制移入不持有 Activity 的 `SystemBars`，旧系统恢复导航栏时保留原有全屏标志。

## 覆盖升级前必须处理的签名兼容性

已实际比对证书：交接包的 1.8.37 release APK 与本机默认 debug keystore 的证书不同。交接文档只保留这一结论，不附本机路径或证书指纹。

虽然两者都使用 debug 签名，密钥口令相同并不代表证书相同。按当前配置直接在本机出包，会使用本机证书，不能覆盖由原证书签名的安装版本。保留原有应用数据的覆盖升级需要原 keystore；本轮没有替换签名、卸载应用或安装测试包。
